# KPM RWBP (Kernel Breakpoint Module)

`kpm_RWBP` 基于 [KernelPatch](./KernelPatch) 框架开发的内核模块，实现了内核态硬件断点以及内核态内存读写功能。

## 项目分支与版本说明

- **`rust-main` 分支（当前分支）**: Rust 版本，利用 Rust 重写的内核模块，为目前的主要开发和维护版本。
- **`main` 分支**: C++ 版本，落后于当前分支。缺少遍历页表直接读取。

---

## 核心功能

- **ARM64 硬件断点管理**: 支持硬件断点寄存器分配与在途任务追踪。
- **高效内存读写**: 支持通过系统调用拦截实现的高性能内核态内存直接读写。*注意:未实现并发安全*
- **跨内核版本兼容**: 适配 Android/Linux 多内核版本的符号解析与链接。仅测试`4.14`,`4.19`,`6.6`。

---

## 构建、部署与测试

在项目根目录下，你可以使用以下命令进行编译和部署：

*   **一键构建**:
    ```bash
    make all
    ```
    *(会自动调用 Cargo 构建 Rust 静态库，并通过 NDK 链接生成 `out/kpm_RWBP.kpm` 内核模块，同时编译测试程序)*

*   **构建并推送至设备**:
    ```bash
    ./scripts/build_and_push.sh all
    ```

*   **运行测试**:
    ```bash
    adb shell su -c "/data/local/tmp/test_rwbp"
    ```

## 已知缺陷

### 1. 手动页表直写的并发安全性缺陷与折衷
* **实现逻辑**：当前的写入路径 [write_process_memory](./src/mm/process.rs#L328-L387) 与读路径一样，采用**手动遍历进程页表**获取物理地址，并直接加上 `linear_voffset` 通过内核线性映射区进行修改。如果物理页无效，则直接中断返回，从而完全规避了缺页侧信道。
* **并发缺陷（TOCTOU 竞态）**：由于采用无锁的手动遍历，且在物理直写前后未对物理页进行锁定（Pin）或双重校验：
  * 在极窄的微秒级时间窗口内，如果目标进程并发释放（`munmap` / `exit`）了该内存页，且该物理页被立刻重新分配给了系统的其他服务，此时进行物理直写会污染无关的物理内存，导致系统 Panic。
* **设计哲学折衷**：根据“减少防御性编程、逻辑直达、错误尽早暴露”的哲学，在实际逆向分析或助手运行等常规场景中，该极端对齐竞态的发生概率接近于零。我们**接受在极端并发冲突下直接触发系统 Panic**，作为一种干净利落的报错方式，以此换取极简、高效且 100% 兼容的无锁直达代码，避免引入臃肿且易引入新漏洞的复杂锁定逻辑。
